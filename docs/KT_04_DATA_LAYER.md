# Hermit Prov — Data Layer Guide

## Overview

All user data is stored locally on the device. There is no server, no sync, and no cloud. Two persistence technologies are used:

| What | Technology | File/Location |
|------|-----------|---------------|
| Custom prompts, journal entries, drill settings, practice history | **Drift (SQLite)** | `hermit_prov.db` in app documents directory |
| App preferences (theme, TTS rate) | **SharedPreferences** | OS-managed key-value store |

Built-in prompts are Dart constants — compiled into the app binary, not stored on disk.

---

## The Drift Database

### Schema (4 tables)

```
CustomPrompts
├── id          TEXT PRIMARY KEY
├── text        TEXT NOT NULL
├── category    TEXT NOT NULL   (PromptCategory.name)
├── createdAtMs INTEGER NOT NULL
└── updatedAtMs INTEGER NOT NULL

DrillSettingsTable
├── drillId     TEXT PRIMARY KEY  (DrillId.name, e.g. "catClock")
└── settingsJson TEXT NOT NULL    (JSON blob — DrillSettings.toJson())

PracticeSessions
├── id          TEXT PRIMARY KEY
├── drillId     TEXT NOT NULL     (DrillId.name)
├── startedAtMs INTEGER NOT NULL
├── durationMs  INTEGER NOT NULL
└── loggedAtMs  INTEGER NOT NULL  (used for streak calculation)

JournalEntries
├── id          TEXT PRIMARY KEY
├── body        TEXT NOT NULL
├── createdAtMs INTEGER NOT NULL
├── updatedAtMs INTEGER NOT NULL
└── drillTag    TEXT              (nullable — DrillId.name)
```

All timestamps are milliseconds since epoch (INTEGER). Drift maps these to `DateTime` in Dart.

### Generated code

`lib/data/local/app_database.g.dart` is generated by Drift's code generator. **Do not edit it manually.** If you change `app_database.dart`, regenerate:

```bash
dart run build_runner build --delete-conflicting-outputs
```

### Database migrations

Currently the schema is at version 1 with no migrations needed. When you add a column or table in a future version, you must increment `schemaVersion` in `AppDatabase` and add a `MigrationStrategy` entry. See Drift's migration docs.

## Domain Models

### AppPreferences
```dart
class AppPreferences {
  final AppThemePreference themePreference;  // system | light | dark
  final double ttsSpeakingRate;              // 0.25–2.0, default 1.0

  static const AppPreferences defaults = AppPreferences(
    themePreference: AppThemePreference.system,
    ttsSpeakingRate: 1.0,
  );
}
```

### PracticeSession
```dart
class PracticeSession {
  final String id;
  final DrillId drillId;
  final DateTime startedAt;
  final Duration duration;
  final DateTime loggedAt;  // used for streak, not startedAt
}
```

**Important:** Streak calculations use `loggedAt`, not `startedAt`. A session that starts at 11:58 PM and runs 5 minutes will have a `loggedAt` just after midnight — it attributes to the next day. This is intentional.

### PracticeStats
```dart
class PracticeStats {
  final Duration totalTime;
  final int sessionsCompleted;
  final int currentStreak;    // consecutive days ending today or yesterday
  final int longestStreak;
  final Map<DrillId, Duration> timeByDrill;
  final Map<DrillId, int> sessionsByDrill;

  static PracticeStats compute(List<PracticeSession> sessions) { ... }
}
```

`PracticeStats` is never persisted. It's computed fresh every time the History screen loads.

### JournalEntry
```dart
class JournalEntry {
  final String id;
  final String body;
  final DateTime createdAt;
  final DateTime updatedAt;
  final DrillId? drillId;  // optional tag

  JournalEntry copyWith({
    String? body,
    DateTime? updatedAt,
    Object? drillId = _sentinel,  // sentinel pattern allows passing null explicitly
  }) { ... }
}
```

The `_sentinel` pattern on `drillId` in `copyWith` allows a caller to explicitly set `drillId` to `null` (untag the entry) while still being able to omit the parameter (keep the existing value). Without this, `copyWith(drillId: null)` would be ambiguous.

### CustomPrompt
```dart
class CustomPrompt {
  final String id;
  final String text;
  final PromptCategory category;
  final DateTime createdAt;
  final DateTime updatedAt;
}
```

### PromptCategory (enum, 8 values)
```
objects | locations | relationships | occupations | emotions | activities | genre | events
```

`PromptCategory.wordBucket` is a constant list of all 8 values. Most drills use it as the default.

## Built-in Seed Prompts

1,661 built-in prompts are compiled into the app across 8 files in `lib/data/seed/categories/`. They are loaded by `buildSeedPrompts()` and passed to `DriftPromptRepository` at construction time.

`DriftPromptRepository` holds the built-in list in memory (it never writes built-ins to SQLite). Custom prompts are stored in SQLite. `getBuiltInPrompts()` returns the in-memory list; custom CRUD hits the database.

Built-in prompt IDs are in the format `bi_<category>_<index>` (e.g. `bi_objects_042`). `DriftPromptRepository` has an `_assertNotBuiltIn` guard that throws if you try to add/update/delete a prompt with a built-in ID prefix.

## Backup / Restore

`LocalBackupService` implements `BackupService`:

```dart
class LocalBackupService implements BackupService {
  Future<AppBackup> buildBackup() { ... }
  Future<String> exportToJson(AppBackup backup) { ... }
  Future<AppBackup> importFromJson(String json) { ... }
  Future<BackupMergeResult> mergeIntoApp(AppBackup backup) { ... }
}
```

**What is backed up:**
- Custom prompts
- Journal entries
- Drill settings
- App preferences (theme, TTS rate)

**What is NOT backed up:**
- Practice history (sessions) — intentional; session history is non-critical metadata
- Built-in prompts — they're part of the app binary

**Merge behavior:**
- Custom prompts and journal entries: skip on duplicate ID (existing local entries are never overwritten)
- Drill settings and preferences: always overwrite with imported values

**Export:** Uses `share_plus` to surface the OS share sheet with the JSON file.  
**Import:** Uses `file_picker` to let the user select a `.json` file.

The backup schema version is `1`. `mergeIntoApp` throws a `FormatException` if the version doesn't match.

## In-Memory Implementations (Tests Only)

All five in-memory repositories live in `lib/data/repositories/in_memory_*.dart`. They hold data in `List` or `Map` fields. Data does not persist across restarts (or between test cases if you construct a fresh instance each time).

`AppServices.withInMemory()` wires all five. Every widget test calls this factory.

**Important:** In-memory repos are `lib` code (not `test` code). This is intentional — `AppServices.withInMemory()` is in `lib/core/di/app_services.dart`, so it needs to reference them from `lib`.
